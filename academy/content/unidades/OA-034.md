## Las piezas de un token

Un token de Solana se construye con varias cuentas:

- **El [[mint|mint]].** Guarda el suministro total, los decimales y dos autoridades: la de emisión y la de congelación.
- **Las cuentas de token.** Cada una guarda el saldo de un mint para un propietario. Si tienes tres tokens distintos, tienes al menos tres cuentas de token.
- **La [[cuenta-de-token-asociada|cuenta de token asociada]].** Es la cuenta de token «por defecto» de una wallet para un mint. Su dirección se calcula a partir de ambas, así que cualquiera puede enviarte un token sin preguntarte dónde guardarlo.

## Las autoridades que hay que mirar

- **[[autoridad-emision|Autoridad de emisión]].** Puede crear más unidades. Si está activa, el suministro puede crecer.
- **[[autoridad-congelacion|Autoridad de congelación]].** Puede congelar cuentas de token, de modo que no puedan mover el saldo.
- **Autoridad de metadatos.** Si los [[metadatos-mutables|metadatos son mutables]], el nombre, el símbolo o la imagen pueden cambiar.

Cada una puede estar activa, en manos de alguien, o haberse revocado para siempre. Lo que conviene anotar es su estado y la fecha en que lo leíste, como en [[OA-022|Interpretar los permisos de un token]].

## Token-2022: la misma idea, con extensiones

Token-2022 es un segundo programa de tokens. Funciona igual en lo básico y añade [[extension-token-2022|extensiones]] que el creador elige al crear el mint. Algunas que conviene reconocer:

| Extensión | Qué permite |
| --- | --- |
| Comisión por transferencia | Retener una parte de cada envío. |
| Delegado permanente | Que una dirección pueda mover o quemar tokens de cualquier cuenta de ese mint. |
| Gancho de transferencia | Ejecutar un programa extra en cada envío, que puede impedirlo. |
| Estado por defecto | Que las cuentas nuevas nazcan congeladas. |
| No transferible | Que el token no se pueda enviar a otra cuenta. |
| Metadatos | Guardar nombre y símbolo en el propio mint. |

Que un token use Token-2022 no lo hace peor. Lo que importa es qué extensiones tiene y quién controla cada una.

## No mezclar ecosistemas

En redes EVM como Ethereum, un token ERC-20 se gestiona con permisos que tú concedes a un contrato (`approve`), como en [[OA-015|Permisos de contratos]]. En Solana existe algo parecido: la [[delegacion-de-tokens|delegación]] de una cuenta de token. Pero las autoridades de emisión y congelación son otra cosa: pertenecen al mint y las controla quien lo creó, no tú.

Cuando leas una ficha, comprueba de qué red habla antes de interpretar un permiso.
