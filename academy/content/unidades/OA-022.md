## Dos permisos básicos

Cuando se crea un [[mint|mint]] en Solana se pueden asignar dos autoridades:

- **[[autoridad-emision|Autoridad de emisión]].** La cuenta que puede crear más unidades. Si está activa, el suministro puede crecer.
- **[[autoridad-congelacion|Autoridad de congelación]].** La cuenta que puede bloquear las cuentas de token de otras personas para que no puedan moverlo.

Cada una puede estar **activa** (asignada a una dirección) o **revocada** (sin dueño, de forma permanente).

## Leer en contexto

El mismo dato significa cosas distintas según el tipo de token:

- En una [[moneda-estable|moneda estable]] respaldada por un emisor, la emisión activa es la forma normal de crear unidades cuando alguien deposita dinero. La congelación puede servir para cumplir órdenes judiciales.
- En un token que dice tener un suministro fijo, una emisión activa contradice esa promesa y merece una pregunta.

Ninguno de los dos casos dice si el proyecto es honesto. Tampoco lo dice un permiso cerrado: una copia que se hace pasar por otro token puede tener las dos autoridades revocadas y seguir siendo una copia.

## Más allá de los dos permisos

El programa Token-2022 añade [[extension-token-2022|extensiones]]: comisiones automáticas en cada transferencia, un delegado permanente que puede mover tokens de cualquier cuenta, transferencias que solo se permiten a cuentas aprobadas, entre otras. Cuando un token usa Token-2022, conviene leer qué extensiones tiene activas.

## Los mismos permisos en las redes EVM

Un token [[erc-20|ERC-20]] o [[bep-20|BEP-20]] no tiene autoridades como campos fijos: lo que pueda hacer alguien depende del código de su contrato. Por eso hay que leer ese código, o su resumen en el explorador si está verificado. Equivalencias habituales:

| En Solana | En un contrato EVM suele aparecer como |
|---|---|
| Autoridad de emisión | Una función `mint` que solo puede llamar el propietario (`owner`) o un rol |
| Autoridad de congelación | Una lista de bloqueo o una función para pausar las transferencias |
| Extensiones de Token-2022 | Código propio: comisiones en cada transferencia, límites por cuenta… |
| Autoridad revocada | Renuncia a la propiedad (`renounceOwnership`) o ausencia de esas funciones |

Hay una diferencia de fondo. En Solana, los tokens SPL usan un programa común, así que la lógica no cambia de un token a otro. En la EVM, cada token tiene su propio código y puede estar detrás de un contrato actualizable (*proxy*): quien controle la actualización puede cambiar las reglas, aunque se haya renunciado a la propiedad.
